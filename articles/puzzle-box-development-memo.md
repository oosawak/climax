# はじめに

これは、`PUZZLE BOX` を `Pixelfork` 上で少しずつ改造していったときのやり取りを、あとから読み返しやすい形にまとめたメモである。

今回の流れは、単に機能を追加しただけではなく、

- パズルの種類を増やす
- トップ画面や設定画面の見た目を整える
- 盤面生成を安定させる
- ライセンスや配布のことまで考える

というふうに、ゲーム全体を少しずつ育てていく流れだった。

## 1. パズルを4種類に増やした

最初の大きな変更は、`Animal Hunt` と `Egg Merge` に加えて、残り2つのパズルを追加したことだった。

追加したのは、

- `NUMBER GROUPS`
- `ANIMAL ESCAPE`

である。

これでトップページから4種類のゲームを選べる構成になった。

## 2. トップページの見た目を正方形タイルに寄せた

トップページは、縦に並ぶ大きな箱や、2行2列の正方形タイルなど、いくつかの見た目を試しながら整えていった。

最終的には、

- 4つのゲームを正方形タイルで見せる
- タイトルを `PUZZLE BOX` にする
- 各ゲームのタイトルをタイル内に入れる
- ゲームを選ぶための案内文を追加する

という方向に寄せた。

途中で、ふわふわ飛ぶ装飾や大きな背面タイルは、見た目を分かりやすくするために外していった。

## 3. 各ゲームに戻る導線を整えた

ゲーム内には、`TOP` に戻るボタンが必要だった。

そのため、

- ゲーム画面上部に説明を1行入れる
- `PAUSE` の左に `TOP` に戻るボタンを置く
- 設定画面では `CLOSE` を見失いにくくする

という調整を行った。

これは、遊びやすさだけでなく、実際に触っているときの迷いを減らすために重要だった。

## 4. ANIMAL ESCAPE を何度も作り直した

このログの中で一番大きく揺れたのが `ANIMAL ESCAPE` である。

最初は、固定テンプレート中心の簡単な盤面だったが、これでは単調で、1手か2手で終わることもあった。

そこで、次のような変更を順番に入れていった。

- 動物を一番上の段から始める
- 障害物の種類や数を増やす
- 盤面をランダム化する
- クリア可能かチェックする
- 解けない盤面なら再生成する

最終的には、完成状態から逆向きに崩す方式を採ることで、解けない盤面を減らしつつ生成速度も上げる方向に進めた。

### 4-1. 盤面生成の改善

単純なランダム生成は、解けない盤面が出やすかった。

そこで、

- 縦2マス
- 横2マス
- 2×2
- 必要な形のブロック

を組み合わせたうえで、ソルバーで確認する方法を試した。

しかしこれでも時間がかかりすぎたため、最終的には「完成状態から逆に崩す」発想へ寄せた。

### 4-2. NEW PUZZLE の差分が見えない問題

NEW PUZZLE を押しても、動物だけが変わって盤面配置がほとんど変わらないことがあった。

原因は、盤面差分の判定やフォールバックの扱いが不十分だったことだった。

そのため、

- 前回盤面との差分を保存する
- 似すぎる盤面は採用しない
- 障害物の配置も変わるようにする

という方向で修正していった。

## 5. EGG MERGE に合成の伸びしろを足した

`EGG MERGE` は、最初は少し簡単すぎたので、難易度と成長の手応えを増やす調整をした。

主な変更は、

- 鷲を合成するとドラゴンになる
- クリア条件をドラゴン3体合成にする
- 動かせなくなったらゲームオーバーにする

という流れだった。

これで、単なる数合わせではなく、合成の先にゴールがある形になった。

## 6. NUMBER GROUPS を一筆書きの操作にした

`NUMBER GROUPS` は、数字を選んでスワイプやカーソル移動で選択する方式に変えた。

つまり、個別クリックだけではなく、

- まず数字を選ぶ
- そのあと隣接マスを一筆書きのようにつなぐ

という遊び方を入れた。

ここで大事だったのは、操作の難しさを上げることではなく、**手触りのある選択操作にすること** だった。

## 7. クリア演出と戻り導線を整えた

全ゲーム共通で、クリア時の演出も整えた。

- クリア直後にすぐリザルトへ飛ばない
- まず `GAME CLEAR!` を出す
- 少し待つか、クリックしたらリザルトへ進む
- 背景は黒で隠さず、紙吹雪やゲーム画面が見えるようにする

これで、クリア演出の気持ちよさを残しつつ、見た目も保てるようにした。

## 8. 設定画面の Credits とプレビューを詰めた

設定画面では、

- `PUZZLE BOX` のプレビューを詰める
- `CLOSE` ボタンを見失いにくくする
- `Credits` を見切れないようにする
- Google Fonts の表記を入れる

という調整をした。

単に見た目を整えるだけでなく、配布や公開を見据えたときの情報整理にもなっている。

## 9. 音をBase64からWeb Audio APIへ置き換える話が出た

SE は、最初は Base64 の MP3 を埋め込んでいたが、ライセンスや配布のことを考えて、Web Audio API で生成する方式が提案された。

この変更の方向性は、

- 外部音源の出所不明問題を避ける
- 商用公開や GitHub 公開をしやすくする
- 音をコード側で管理しやすくする

という意味で重要だった。

## 10. ライセンスを考える流れに進んだ

このゲームを GitHub で公開したい、Steam や Android で配りたい、という話が出たことで、ライセンスの確認も必要になった。

特に確認対象になったのは、

- Google Fonts のフォント
- 絵文字ベースのアイコン
- SE

である。

ここでは、コードだけでなく、**素材の出所をはっきりさせること** が大事だった。

## このログから分かること

この `PUZZLE BOX` の作業で見えたのは、AI を使ったゲーム開発は、機能を1個ずつ足すだけではなく、見た目、操作性、生成速度、配布条件まで含めて少しずつ整える作業だということだった。

- パズルを増やす
- 盤面を面白くする
- UI を分かりやすくする
- クリア演出を整える
- 音や素材の扱いを明確にする

この積み重ねで、ゲームが「動くもの」から「出せるもの」に近づいていった。

## まとめ

`PUZZLE BOX` の改造は、AI に何かを一発で作らせるのではなく、問題が出るたびに少しずつ直して完成度を上げていく流れだった。

特に大事だったのは次の点である。

- 4種類のパズルに広げたこと
- `ANIMAL ESCAPE` の盤面生成を何度も見直したこと
- `EGG MERGE` と `NUMBER GROUPS` に遊びの幅を足したこと
- クリア演出と戻り導線を整えたこと
- ライセンスや配布のことまで含めて考えたこと

このメモは、AI と一緒にゲームを育てるときの、かなり実践的な記録になった。
