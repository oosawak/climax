# 第１章 〜ノートPCを持ち歩く時代は終わった 〜
##  はじめに
この春、始めたこととして AIによる本格的なシステム開発を始めました。
そこで得た経験から、最近は携帯電話からの自宅のPCに会話で仕事を依頼して、帰宅後PCで作業をしたりしてるので、その仕組みなどを紹介したいと思います

## 1-1. いつでも、どこでも、開いた瞬間にAIと同期する
カフェで、電車の中で、あるいはベッドの上で。「今、この瞬間にコードを書きたい、アイデアを試したい」と思ったとき、わざわざ重いノートPCを開いて、スマホのテザリングを繋いで、起動を待つ……そんな時代はもう終わりにしましょう。

手元にあるスマートフォンと、自宅で眠っているサーバー（あるいは普段使いのPC）をセキュアなネットワークで結びつければ、「いつでも、どこからでも、画面を開いた瞬間にAIと同期して爆速開発ができる環境」が手に入ります。

## 1-2. スマホは文字を打つ道具ではなく、AIを操る「コントローラー」である
「スマホの小さな画面とバーチャルキーボードで、長大なコードを手入力するなんて絶対に無理だ」と思うかもしれません。それは完全に正しい感覚です。

だからこそ、本書で紹介するのは従来の「手入力によるコーディング」ではありません。スマホから　AI（GitHub Copilot、Codex、Claude 3.5 Sonnet など）に対して短い日本語で指示（詠唱）を出し、バックエンドのサーバー上でリアルタイムにコードを生成・修正させていく**「AI駆動型ライブコーディング」**の体系です。

スマートフォンは長文を打つ道具ではなく、世界最強の AI たちを遠隔から操るための「魔法のコントローラー」へと変貌するのです。

## 1-3. 本書で手に入る「未来のライブコーディング体験」
本書を読み終え、環境を構築した後に待っていｓるのは、以下のような未来です。

* 通勤電車の中： スマホを取り出し、 AIに「Pythonで自動スクレイピングするスクリプトを作って」と1行指示を出す。数秒後、自宅のサーバー側で完璧なコードが自動生成され、Gitへのコミットまで完了する。

* カフェでの休憩中： 「Next.jsで新しい管理画面のモックを作っておいて」とスマホから指示。自宅のMac miniが動き出し、APIとフロントエンドのUIコンポーネントが一瞬で組み上がる。

* 自宅のデスク： スマホで仕込んだコードの続きを、PCの大画面とVS Code、そしてChromeの検証ツール（F12）を使って、何一つ繋ぎ変えることなくシームレスにデバッグする。

場所の制約、画面サイズの制約を超越する、新しい開発ライフを今ここから始めましょう。

# 第2章：全体像と「器（ハードウェア）」の選択肢・初期設定
## 2-1. システムの全体アーキテクチャ
本システムは、手元の「スマートフォン（クライアント）」から、Tailscaleという安全な仮想ネットワークの回廊を通り、自宅の「母艦サーバー（Linux/Mac）」へSSH接続します。そして、サーバー内に常駐させたAIツールをコマンドライン（CLI）から叩くことで、コード生成や環境の構築、デプロイを実現します。

## 2-2. あなたの環境に合わせて選ぶ4つの神殿（母艦サーバー）
あなたが用意する母艦サーバーは、予算や手持ちの機材に合わせて、以下のような選択肢から自由に選ぶことができます。

### M4 Mac mini

わずか12.7cm四方の極小ボディでありながら、圧倒的な省電力を両立。最大64Gメモリーがあるとの広大なユニファイドメモリを活かして、巨大なローカルAI（LLM）のモデルをローカルでサクサク動かせる最高峰の環境です。24時間つけっぱなしにしてもほぼ無音で、電気代も気になりません。LLMを利用しなければ、16Gのメモリーでも充実利用が可能です。

### グラボ付きUbuntuマシン

RTXシリーズなどの強力なGPUを積み、ローカルでのAI生成やヘビーなコンパイルを力技でねじ伏せる、自作PC派・Linuxガチ勢向けの環境。Local LLM や ComdyUI を利用する場合もオススメです。またグラボは必須ではないでしすし、RTXじゃなくていいですし、iGPUでもいいです。cuda、RCOm、pyTouchのインストールは本書では取り扱いません。

### Windows（WSL2：Windows Subsystem for Linux）

普段使っているWindows PCの中にLinux環境（Ubuntu）を構築する、追加投資ゼロの一番手軽なスタイル。外部のAPI（ClaudeやCopilot）を中心に使うならこれで十分すぎるほど戦えます。

### ラズベリーパイ（Raspberry Pi 4 / 5）

本体代数千円〜1万円程度、電気代はタダ同然。自宅のルーターにLANケーブルを挿しておくだけで、外出先のスマホからいつでもアクセスできる「常時起動の魔導拠点」が格安で手に入ります。（※ラズパイ自体にグラボはないため、ClaudeなどのクラウドAPI連携が前提となります）

## 2-3. 母艦となるOSに、ベースとなるUbuntu（Linux）環境と、SSHで接続するための受け口を作ります。
【Windows（WSL2）の場合】

Windowsの「ターミナル（PowerShell）」を管理者権限で起動し、以下のコマンドを1行打つだけでUbuntuがインストールされます。

```sh
wsl --install -d Ubuntu
```

インストール後、PCを再起動するとUbuntuが立ち上がり、ユーザー名とパスワードの設定を求められるので、忘れないように設定してください。

【Ubuntu / ラズパイ / Macの場合】

ターミナルを開き、外部からの通信（SSH）を受け付けるためのパッケージをインストールして起動します。（※Macの場合は「システム設定」＞「一般」＞「共有」から「リモートログイン」をオンにするだけでOKです）。

```sh
# Ubuntu/ラズパイでのSSHサーバーインストール
sudo apt update
sudo apt install openssh-server -y

# SSHサービスの起動と常時有効化

sudo systemctl start ssh
sudo systemctl enable ssh
```

# 3. 遠隔を結ぶ回廊（Tailscale）と常時起動の空間（tmux）
## 3-1. 導路術（Tailscale）で世界中のどこからでも安全に自宅へ繋ぐ
通常、外出先から自宅のPCやサーバーにアクセスするためには、自宅のルーターの設定画面を開いて「ポート開放」をしたり、固定IPアドレスを契約したりという非常に面倒でセキュリティリスクの高い作業が必要です。

これを一瞬で解決するのが Tailscale（テイルスケール） です。

Tailscaleは、設定不要で安全なプライベートネットワーク（メッシュVPN）を構築してくれる神サービス

```sh
# Tailscaleをインストール
curl -fsSL https://tailscale.com/install.sh | sh

# Tailscaleを起動し、認証リンクを表示
sudo tailscale up
```

画面に https://login.tailscale.com/a/xxxx のような認証用URLが表示されるので、PCやスマホのブラウザでアクセスし、ログインして端末を承認してください。

承認が完了すると、そのマシン専用のIPアドレス（例：100.115.x.x）が発行されます。**このIPアドレスをメモしておいてください。外からスマホで繋ぐ際の「宛先」になります。**

## 3-2. 時間の間（tmux）で通信が切れても開発を永続化する
スマートフォンによるモバイル開発において、最大の敵は**「電波の瞬断（地下鉄に入った時などに通信が切れること）」**です。

普通のSSH接続だと、通信が切れた瞬間に実行中だったプログラムは強制終了し、エディタで書いていた未保存のコードは消し飛びます。

この絶望を防ぐために、サーバー側に tmux（ティーマックス） を導入します。

tmuxはターミナルを仮想的に維持してくれるツールです。スマホの回線が一瞬切れてSSHが切断されても、サーバー側のtmux空間の中ではエディタも AIの処理も全く動じることなく「時間が止まったように」実行され続けます。

電波が復帰したあと、スマホから再接続して「 tmux セッション名」 と1行打つだけで、一瞬にして「さっきまで作業していた画面」に完全復旧できます。

###📥 tmuxのインストール（Mac）

Mac（macOS）で tmux をインストールする最も簡単で一般的な方法は、パッケージマネージャーの Homebrew を使用することです

まずはhomebrewをインストールします。

```sh
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
　Homebrewが用意できたら、次のコマンドを実行するだけでインストールが完了します。

brew install tmux
```

###📥 tmuxのインストール（Ubuntu）

sudo apt install tmux -y
これで母艦サーバー側の基礎的な「器（ハードウェア）」と「回廊（ネットワーク）」の準備はすべて整いました。

## 5-2. すべての鍵となる「GitHub CLI（gh）」のインストール
これから導入する「GitHub Copilot CLI」は、GitHub公式のコマンドラインツールである gh の拡張機能として動作する。そのため、まずは母艦に gh コマンド本体をインストールしてください

### 🐧 Ubuntu（物理サーバー・WSL2・ラズパイ）の場合

aptでもインストールできますが、古いバージョンしか入っていないことがあるため、GitHubの公式リポジトリを登録して最新版をインストールしてます。

```sh
# GitHub公式リポジトリの鍵を追加し、最新の 'gh' をインストールする
type -p curl >/dev/null || (sudo apt update && sudo apt install curl -y)

curl -fsSL https://cli.github.com/packages/githubcli-archive-keyring.gpg | sudo dd of=/usr/share/keyrings/githubcli-archive-keyring.gpg \
&& sudo chmod go+r /usr/share/keyrings/githubcli-archive-keyring.gpg \
&& echo "deb [arch=$(dpkg --print-architecture) signed-by=/usr/share/keyrings/githubcli-archive-keyring.gpg] https://cli.github.com/packages stable main" | sudo tee /etc/apt/sources.list.d/github-cli.list > /dev/null \
&& sudo apt update \
&& sudo apt install gh -y

# インストール確認
gh --version
```

```text
# =====================================================================

# Climax AI Shortcuts for Smartphone Coding

# =====================================================================

# 1文字『p』だけでGitHub Copilotを起動し、開発計画やシェルコマンドを生成

alias p="gh copilot suggest -t shell"

# 1文字『x』だけでエラーログや不具合の原因、難解なコマンドの意味を解説させる

alias a="aider --model anthropic/claude-3-5-sonnet --auto-commits"

alias tｍ="tmux a -t dev || tmux new -s dev"
```

## 5-5. Vim / Neovim × GitHub Copilot の導入とスマホ用キーバインド(参考)
スマホからサーバー上のファイルを直接編集（ライブコーディング）する際、エディタ内でAIのリアルタイムな「コード補完」を受け取るための設定です。

### 📥 導入手順（母艦側で実行）

ここでは定番のプラグインマネージャーである vim-plug を使った導入例を示すします。
```sh
mkdir -p ~/.vim/pack/github/start git clone https://github.com/github/copilot.vim.git ~/.vim/pack/github/start/copilot.vim
```

Vim上で :Copilot setup と打ち込み、画面に出たワンタイムコードを使ってGitHubアカウントと連携させると利用出来ます。

### ⌨️基本的な使い方
コードを書いていると、薄いグレーの文字で続きのコードが提案（レコメンド）されます。

提案を受け入れる: Tab キーを押す
次の提案を見る: Alt + ] （Macは ⌥ + ]）
前の提案を見る: Alt + [ （Macは ⌥ + [）
提案をキャンセル: Ctrl + ]

### 📱 スマホ最適化：Tabキー代替（Ctrl + J）のキーバインド（秘伝）

通常のPC環境であれば、Copilotが提案してきた薄グレーのソースコードは Tab キーを押すことで確定（Accept）させます。しかし、**スマホのバーチャルキーボードにTabキーはないか、あっても端にあって非常に押しにくい。**

そこで、スマホの親指フリックでも、キーボード上のボタンでも一瞬で入力できる Ctrl + J に確定バインドを強制変更します。.vimrc に以下を記述しましょう。

```sh
" デフォルトのTabによる確定マッピングを無効化する
let g:copilot_no_tab_map = 1

" 挿入モード中、Ctrl + J でAIのコード提案を一瞬で確定（Accept）する

imap <silent><script><expr> <C-j> copilot#Accept("\<CR>")
```

これで世界が変わります。スマホ画面上でVimを開き、コードを1行書き始めると、AIが「その後に続く数十行のコード」を薄グレーで提案してくれます。貴方はスマホ画面の [Ctrl] を押し、**[J]** をポンとタップする。これだけで、一瞬にして正確な関数やロジックがエディタに美しく展開されます。

# 6. 【技術深掘り】AIがファイルを自動修正する「パッチ適用（Diff/Patch）」の裏側
スマホから指示を出したとき、AiderやCodexといったツールが、一瞬にして何千行もあるソースコードの「特定の1行」だけを正確に書き換える様子を目にするだろう。裏側で一体何が起きているのか。その魔術の正体は、古くからLinuxの世界で使われてきた**「パッチ（Patch）当て」**の思想である。

## 6-1. なぜファイル全体を書き換えないのか？
AIにコードを修正させる際、最も愚かなアプローチは「ファイル全体を再生成させること」だ。これには3つの巨大なデメリットがある。

### 1. トークン（電気代・API費用）のドブ捨て： 10行直すために1000行のファイルを全出力させれば、莫大なトークン費用がかかる。

### 2. 速度の低下： スマホの回線において、AIがダラダラと長文を出力するのを待つのは苦痛でしかない。

### 3. デグレード（不具合の混入）： 直してほしくない別の正常なコードまで、AIの気まぐれで勝手に書き換えられてしまうリスクが跳ね上がる。

そのため、優れたCLI AIツールは、AIに「差分（Diff）」だけを出力させ、それを母艦側のスクリプト（PythonやPerlなど）で元のファイルにパッチ適用する仕組みを採用している。

## 6-2. 現代AIツールの共通言語
「SEARCH/REPLACE ブロック」

例えば、Aiderなどの最先端ツールが内部でClaudeやGPTとやり取りする際、AIは以下のような**「SEARCH/REPLACE ブロック」**と呼ばれる特殊な形式のパッチを出力している。

```text
<<<<<<< SEARCH

def calculate_total(price):

return price * 1.1

=======

def calculate_total(price, tax_rate=0.1):

return price * (1 + tax_rate)

>>>>>>> REPLACE
```

母艦側で待機しているPythonやPerlのパーススクリプトは、ファイル内から <<<<<<< SEARCH に挟まれたコードを高速で検索し、それを ======= の下にある新しいコードへと置換（パッチ適用）する。これこそが、スマホの細い回線でも、1秒足らずで正確無比にコードが書き換わる仕組みです。

# 7. AIを支配する「トピック（機能単位）開発」の美学
前章で学んだ「パッチ適用」の力を120%活かすために、本書で最も賞賛すべき**「究極のスマート開発手法」**を解説します。

それは、思いつきで全ファイルをめちゃくちゃに書き換えるのではなく、**「実装したい機能を小さな『トピック』として綺麗に切り出し、AIにそのトピックだけを集中攻略させる」**という、Topic-based（機能単位）開発の戦略です。

## 7-1. なぜ「トピック開発」がスマホ環境で最強なのか？
スマホの小さな画面、限られた視界において、巨大なプロジェクトの全体像を同時に追いかけるのは人間の脳にとっても負担が大きい。

そこで、開発を「ログイン機能の実装」「バグの修正」「UIの微調整」といった、独立した**『トピック』**に細分化します。

この手法の何が素晴らしいのか。それは、**AI（GitHub CopilotやAider）の脳細胞（コンテキスト）を完全に1つのタスクにロックオンさせられる点**にあります。「今はこのトピック（機能）だけを考えてくれ」と境界線を引いてやることで、AIの出力の精度は狂気的なまでに跳ね上がる。

7-2. 精霊に「トピック」を命じる圧倒的スマートさ
実際の運用では、Gitのトピックブランチの作成すらも、スマホのCLIからAI（Copilot CLIやAider）に丸投げします。

### スマホからの詠唱：
p "新機能（ユーザー認証）のためのGitトピックブランチを作って切り替えて"
AIが即座に git checkout -b feature/user-auth を提案・実行する。

ここからが天才術師の真骨頂です。ブランチを切り替えたら、AIにそのトピックの「設計書（プロンンプト）」を1行投げるだけす。

Aiderなどのツールは指定したトピックを実装するために必要なファイルだけに精密な「パッチ」を当て、機能が完成したら**「そのトピックにふさわしい綺麗なコミットメッセージ」を自動生成して自動コミット**まで完了させます。

## 7-3. 混沌を排除し、秩序をもたらす
だらだらとコードを書いて歴史を汚す凡百のエンジニアを横目に、スマホを片手に、

「トピックを切り出す ➡ AIがパッチを当てる ➡ 自動コミット ➡ 次のトピックへ」

という、あまりにも美しく洗練された、秩序ある高速開発ループを回し続けてください。

スマホという制約を、逆に「タスクをモジュール化（細分化）してAIのポテンシャルを最大化する」という最強の武器に転換する。この設計思想に辿り着いたとき、PCの前に縛られている凡百のプログラマーを遥か高みから追い抜くことになるかもしれません。
